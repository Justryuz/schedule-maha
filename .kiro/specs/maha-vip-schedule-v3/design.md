# Design Document: MAHA VIP Schedule v3

## Overview

This design upgrades the existing MAHA VIP Schedule Dashboard from a desktop-first table layout to a responsive, mobile-first card-based interface. The upgrade adds mobile-specific components (card layout, bottom navigation, date tabs, filter bottom sheet, VIP badges) while preserving all existing desktop functionality. The implementation uses only vanilla HTML, CSS, and JavaScript — no frameworks or build tools.

## Architecture

The existing architecture is retained and extended:

```
index.html          ← Single-page app (add new mobile HTML elements)
css/style.css       ← All styling (add mobile component styles + media queries)
js/app.js           ← Main logic (add mobile rendering functions + viewport detection)
js/pdf-export.js    ← PDF generation (unchanged)
```

**Key principle**: Desktop behavior remains untouched. Mobile components are additive — they are hidden on desktop via CSS media queries, and mobile rendering logic is gated behind a viewport width check in JavaScript.

### 3. VIP Badge Color Mapping

A deterministic color assignment based on VIP name hashing to ensure consistent colors across renders.

```javascript
const VIP_BADGE_COLORS = [
    '#e74c3c', '#3498db', '#2ecc71', '#9b59b6', '#f39c12',
    '#1abc9c', '#e67e22', '#16a085', '#8e44ad', '#d35400',
    '#2980b9', '#27ae60', '#c0392b', '#7f8c8d', '#2c3e50'
];

function getVipBadgeColor(vipName) {
    const trimmed = vipName.trim().toUpperCase();
    let hash = 0;
    for (let i = 0; i < trimmed.length; i++) {
        hash = ((hash << 5) - hash) + trimmed.charCodeAt(i);
        hash = hash & hash; // Convert to 32-bit integer
    }
    return VIP_BADGE_COLORS[Math.abs(hash) % VIP_BADGE_COLORS.length];
}

function renderVipBadges(vipString) {
    if (!vipString) return '';
    return vipString.split(',')
        .map(name => name.trim())
        .filter(name => name.length > 0)
        .map(name => `<span class="vip-badge" style="background-color:${getVipBadgeColor(name)}">${escapeHtml(name)}</span>`)
        .join('');
}
```

```javascript
function renderDateTabs() {
    if (!isMobile()) return;
    const container = document.getElementById('dateTabsScroll');
    const today = new Date();
    today.setHours(0, 0, 0, 0);

    container.innerHTML = availableDates.map((dateInfo, idx) => {
        const diff = Math.round((dateInfo.obj - today) / (1000 * 60 * 60 * 24));
        const label = getDateTabLabel(dateInfo, diff);
        const activeClass = idx === currentDateIndex ? 'active' : '';
        return `<button class="date-tab ${activeClass}" data-index="${idx}">${label}</button>`;
    }).join('');
}

function getDateTabLabel(dateInfo, dayDiff) {
    if (dayDiff === -1) return 'SEMALAM';
    if (dayDiff === 0) return 'HARI INI';
    if (dayDiff === 1) return 'ESOK';
    return `${dateInfo.obj.getDate()} ${BULAN[dateInfo.obj.getMonth()].substring(0, 3).toUpperCase()}`;
}
```

```javascript
function switchTab(tabId) {
    // Existing top nav update
    document.querySelectorAll('.nav-tab').forEach(tab => {
        tab.classList.toggle('active', tab.dataset.tab === tabId);
    });
    // Bottom nav update
    document.querySelectorAll('.bottom-nav-item').forEach(item => {
        item.classList.toggle('active', item.dataset.tab === tabId);
    });
    // Tab content
    document.querySelectorAll('.tab-content').forEach(content => {
        content.classList.toggle('active', content.id === `tab-${tabId}`);
    });
    if (tabId === 'eksekutif' && allData.length > 0) {
        setTimeout(() => renderCharts(), 100);
    }
}
```

## Rendering Strategy

The render functions check `isMobile()` and produce either table HTML or card HTML:

```javascript
function renderUtamaTable(data) {
    if (isMobile()) {
        renderUtamaMobileCards(data);
        return;
    }
    // Existing table rendering logic (unchanged)
    const tbody = document.getElementById('scheduleBodyUtama');
    // ...
}

function renderUtamaMobileCards(data) {
    const container = document.getElementById('mobileCardsUtama');
    if (data.length === 0) {
        container.innerHTML = '<div class="empty-state">...</div>';
        return;
    }
    container.innerHTML = data.map(item => `
        <div class="schedule-card">
            <div class="card-time">${escapeHtml(item.masa)}</div>
            <div class="card-body">
                <div class="card-program">${escapeHtml(item.program)}</div>
                <div class="card-lokasi"><i class="fas fa-map-marker-alt"></i> ${escapeHtml(item.lokasi)}</div>
                <div class="card-vips">${renderVipBadges(item.vip)}</div>
            </div>
        </div>
    `).join('');
}
```

## Error Handling

| Scenario | Behavior |
|----------|----------|
| CSV fetch fails | Falls back to hardcoded sample data (existing behavior) |
| Auto-refresh fails | Silent failure, no UI disruption (existing behavior) |
| Empty filter results | Shows empty state message card on mobile / table empty state on desktop |
| Invalid VIP string (empty/null) | `renderVipBadges` returns empty string |
| Resize during animation | Debounced resize handler prevents multiple re-renders |
| Filter sheet open during tab switch | Automatically closes filter sheet |

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system — essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Viewport-conditional rendering output

*For any* array of schedule entries, if the viewport is below 768px the render function SHALL produce card-based HTML (one card element per entry), and if the viewport is 768px or wider it SHALL produce table-row HTML (one `<tr>` per entry).

**Validates: Requirements 1.1, 1.2**

### Property 2: Card content completeness

*For any* valid schedule entry with non-empty time, program, lokasi, and VIP fields, the card render output SHALL contain all four field values in the generated HTML string.

**Validates: Requirements 1.3**

### Property 3: VIP badge count matches comma-separated names

*For any* non-empty VIP string containing N comma-separated names (after trimming), the `renderVipBadges()` function SHALL produce exactly N badge elements.

**Validates: Requirements 1.5, 2.3**

### Property 4: VIP plain text on desktop

*For any* schedule entry rendered when the viewport is 768px or wider, the VIP field SHALL appear as plain text without any badge (`<span class="vip-badge">`) elements in the output.

**Validates: Requirements 1.6, 2.4**

### Property 5: VIP badge color determinism and distribution

*For any* VIP name, `getVipBadgeColor()` SHALL always return the same color for the same name (deterministic), and *for any* two distinct VIP names, their assigned colors SHALL differ unless the palette is exhausted (palette size = 15).

**Validates: Requirements 2.2**

### Property 6: Relative date label correctness

*For any* date, `getDateTabLabel()` SHALL return "SEMALAM" if the date is exactly 1 day before today, "HARI INI" if the date equals today, "ESOK" if exactly 1 day after today, and a formatted date string for all other dates.

**Validates: Requirements 3.2**

### Property 7: Date-based schedule filtering

*For any* dataset and any selected date, filtering by that date SHALL return only entries whose `tarikh` field matches the selected date key, and SHALL return all such matching entries.

**Validates: Requirements 3.3**

### Property 8: Tab switching activates correct content

*For any* valid tab ID from the set {"utama", "jadual-penuh", "eksekutif"}, calling `switchTab(tabId)` SHALL result in exactly one tab content section being active (the one matching the ID) and all others inactive.

**Validates: Requirements 4.3, 10.1**

### Property 9: Combined filter logic correctness

*For any* dataset and any combination of filter criteria (program, lokasi, VIP, search keyword), the filtered result SHALL contain exactly those entries that match ALL active (non-empty) filter criteria simultaneously, where search matches case-insensitively across program, lokasi, and VIP fields.

**Validates: Requirements 5.4, 8.2**
